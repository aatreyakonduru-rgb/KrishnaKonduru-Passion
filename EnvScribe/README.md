# EnvScribe

A read-only agent that crawls an engineering environment, journals what it finds, and packages the result as a sanitized zip. It can also answer questions about the journal, and in Advise mode it proposes code changes for a requirement.

> Status: built and unit-tested locally (88 tests) and run against the bundled `sample/` project only. **Nothing has been run against real systems.** See [Unverified assumptions](#unverified-assumptions).

## What it does

- **Source code, any language** – symbols, imports, endpoints, DB/connection usage (`scribe/scanners/code.py`).
- **Build and dependencies** – pom.xml, Gradle, npm, pip, etc. (`scanners/build.py`).
- **API contracts** – OpenAPI, protobuf, GraphQL, WSDL and similar (`scanners/contracts.py`).
- **Configs and per-environment parameters** – sit/dev/uat/prod (`scanners/config.py`).
- **CI/CD and IaC** – pipelines, Kubernetes, Terraform, cloud (`scanners/cicd_iac.py`).
- **Secret and leak detection** – `scanners/leaks.py`.
- **Documents** – PDF (OCR fallback if tesseract exists), DOCX, XLSX, PPTX, drawio/vsdx/BPMN/SVG/PlantUML/Mermaid, transcripts with speakers and names removed (`scribe/docs/`).
- **Service connectors** (read-only): Bitbucket, Jira, Confluence, Artifactory, Bamboo, SonarQube, Snowflake, RDS and more (`scribe/connectors/`). DB catalogs are metadata only (`dbcatalog.py`).
- **Relevance gate** – only reads documents related to applications found in the code. Uploads can be tagged or read anyway.
- **Viewer** (`/viewer`) – read-only browser for the output zip: file tree, rendered Markdown with working links, and a searchable facts table. Open the current run's zip or any journal zip from disk.
- **Exit button** – in the UI header; cancels any active run (a partial zip is still produced) and stops the server.
- **Q&A and Advise** – hybrid search over the journal (`knowledge.py`, `features/semantic.py`). Advise and Impact output is labeled PROPOSAL and is suggest-only.

Images, video and audio are not read.

## Analysis features

An **analysis** stage runs after the journal is written and before the two sweeps (`scribe/features/`, one module per feature, each isolated so a failure in one never stops the run). Everything it writes goes through the same redaction, both sweeps and the sealed-zip rescan. Every derived statement records its rule and cites its evidence.

| # | Feature | Output (inside the zip) | Module |
|---|---|---|---|
| 1 | Dependency and architecture graph (JSON, Mermaid, C4). Service-to-service calls are linked only when a URL **path** equals exactly one other service's endpoint path; hosts are never used | `graph/` | `graph.py` |
| 2 | Environment drift (SIT vs UAT …) and run-to-run diff | `drift/` | `drift.py`, `history.py` |
| 3 | SBOM (CycloneDX 1.5, SPDX 2.3) and license report. Licenses are never guessed; unknown stays unknown | `sbom/` | `sbom.py` |
| 4 | Service catalog: Backstage `catalog-info.yaml`, CMDB CSV and JSON. Owner is a team or `unknown`; no links | `catalog/` | `catalog.py` |
| 5 | Scorecards and risk flags per service | `scorecards/` | `scorecards.py` |
| 6 | Living docs: architecture, runbook, ADR drafts (each labeled draft) | `docs-generated/` | `livedocs.py` |
| 7 | Data lineage from SQL in code (sqlglot), joined to DB catalog metadata when present | `lineage/` | `lineage.py` |
| 8 | Hybrid search (BM25 + vector) in Ask | UI / API | `semantic.py` |
| 9 | Change impact and PR-draft text (suggest-only PROPOSAL; nothing is written or executed) | UI / API | `impact.py` |
| 10 | API contract diff (breaking changes vs the previous run) | `contracts/changes.md` | `contract_diff.py` |
| 11 | Migration and cloud readiness | `readiness/` | `readiness.py` |
| 12 | Git-history secret scan. Reports file, commit short-id and detector only; never the value, message, author or email | `git-history/` | `gitscan.py` |
| 13 | Live cloud and Kubernetes inventory compared with IaC (opt-in) | `live/` | `cloudinv.py` |
| 14 | Runtime correlation from an APM export (opt-in) | `runtime/` | `runtime.py` |
| 15 | Ownership: **teams only**. Individuals and ambiguous owners are omitted and counted | `ownership/` | `ownership.py` |

Disable any of them with `disabled_features` in `targets.yaml` (or the Setup tab). Toggling these settings does not discard scan progress.

### Viewer

`/viewer` has a **Graph** tab: an interactive node/edge view of `graph/graph.json` (no external libraries). Click a node to see each connection's class, rule and evidence. Dashed lines are DOCUMENTED claims, not verified against code. Mermaid and C4 blocks in `.md` files are shown as text.

### Ask and Impact

The Ask tab has two boxes. **Ask** answers with citations or says "not found". **Impact of a change** (`GET /api/impact?q=...`) lists the files, consumers, config keys per environment, tests and teams the journal says are affected, with the citation for each, plus PR-description text. No code is generated by this route.

Hybrid search limitation: the default vector part is a local TF-IDF over word stems and character trigrams. It copes with plurals, spelling variants and camelCase/snake_case but **does not understand synonyms** and is not a language-model embedding. Pass an `embedder` to `HybridIndex` for true semantic matching (unverified here). A relevance threshold still applies, so unrelated questions answer "not found". Turn it off with `semantic_search: false`.

### Drift needs a second run

Run history is stored in `<output_dir>/history/<run_id>.json`. That folder is **outside the journal, so it is never swept or zipped**. The first run reports `UNKNOWN: first run`; a second run in the same output folder produces real differences (changed config values, added or removed endpoints, breaking contract changes).

### Runtime export formats

Drop exports from your APM tool into `runtime_dir` (default `<output_dir>/runtime-maps`). Nothing is fetched from the APM tool. Two shapes are read (`.json` or `.csv`):

```json
{"window": "7d",
 "edges": [{"from": "svc-a", "to": "svc-b", "calls": 1200, "errors": 3}],
 "endpoints": [{"service": "svc-a", "method": "GET", "path": "/payments/42", "calls": 10}]}
```

```
source,target,calls,errors          # edges (errors optional)
service,method,path,calls           # endpoints
```

Service names are matched to crawled repository names after lower-casing and dropping punctuation (`Pay-API` = `payapi`); names that match nothing are listed and never guessed. Findings: runtime calls the code does not show, code paths with no traffic (which does not prove they are dead), and endpoints with no traffic.

### Live cloud inventory (opt-in)

Set `cloud_inventory` to any of `aws`, `gcp`, `azure`, `kubernetes`. EnvScribe calls the CLIs **already logged in on this machine** (`aws`, `gcloud`, `az`, `kubectl`); it stores no credentials. A single allow-listed runner permits only list/describe/get style commands, refuses any mutating or secret-reading word, never reads Kubernetes secrets, and audits each command. Addresses, endpoints, usernames and tag values are dropped before a fact is built. A missing CLI or login is reported as UNKNOWN. Parsers are tested against fixture-shaped output only; see below.

### Vulnerability lookup (opt-in) and privacy

`vuln_lookup: true` sends **package names and versions only** to `api.osv.dev` and records advisory ids. It is off by default because it leaves this machine. Nothing else is sent.

### DB catalogs

`db_catalogs` in `targets.yaml` lists metadata-only catalogs (`engine: postgres | snowflake`). Credentials come from the environment (`PG*` variables; `SNOWFLAKE_*`). A catalog that cannot be read becomes an UNKNOWN fact, not a failure. Optional packages: `psycopg[binary]`, `snowflake-connector-python`.

## Grounding policy

Fact classes: OBSERVED, DERIVED (records its rule), DOCUMENTED, DISCUSSED, LLM_DESCRIBED (must quote evidence), UNKNOWN. Every fact carries evidence. Conflicts are reported, never resolved. When nothing matches, answers say "not found". Everything is read-only.

## Output safety

- IPs and hostnames are **always masked**; there is no setting to allow them.
- Two blocking sweeps run before zipping: **Privacy & security** and **Credential & secret**. If one finds something, EnvScribe auto-redacts, rescans, then blocks if anything remains. The sealed zip is rescanned and verified.
- `progress.jsonl` lets an interrupted run resume. Cancelling produces a partial zip.
- Download the zip right away; the VM is ephemeral.

## Settings

- Token budget: `0` or blank = unlimited.
- Max workers: 1–100 (local thread pool; the worker/package design is backend-agnostic).

## Setup

```powershell
git submodule add https://github.ibm.com/AI-CoE/aicoe-agent-utils.git   # needs credentials
git submodule update --init --recursive
python -m venv venv; .\venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env      # fill in credentials; auth flags stay false by default
```

Optional: `pip install aicoe-agent-utils[agentops]`, `pytesseract` for OCR.

## Run

```powershell
python main.py --ui-only      # web UI only, no LLM/A2A needed; http://127.0.0.1:8090
python main.py                # A2A server + UI (needs aicoe-agent-utils and LLM config)
python test_client.py         # A2A test client
python scripts/run_sample.py  # end-to-end run on sample/
python -m pytest tests -q
```

Copy `targets.example.yaml` to `targets.yaml` to describe sources and environments.

main.py, config.py, envscribe_agent.py, a2a_factory.py, test_client.py

## Unverified assumptions

0. **The analysis features are tested with fixtures and the bundled sample only.** In particular live cloud inventory (13), APM import (14), the OSV lookup, and the Snowflake/Postgres catalogs have not been run against real systems. The default hybrid search is not a language-model embedding.

1. **aicoe-agent-utils API names.** The repo could not be cloned (no credentials). `envscribe_agent.py`, `a2a_factory.py`, `main.py` and `test_client.py` use guessed imports (`aicoe_agent_utils.agent.BaseLangGraphAgent`, `aicoe_agent_utils.a2a.A2AAgentFactory`, `aicoe_agent_utils.utils.start_a2a_server`) with stand-in classes. Compare with `aicoe-agent-utils/examples/agents_with_mcp/weather_agent/` once cloned.
2. Whether the Devin VM can serve the UI, and how Devin sub-sessions return chunks (currently left to Devin).
3. Snowflake headless auth: use OAuth token or key-pair, not `externalbrowser`.
4. DB catalogs configured in `db_catalogs` are invoked from `Run._connectors`, but only tested with an injected query runner.
5. OCR, `snowflake-connector` and `pymupdf` are optional and not installed here; OCR degrades to "no text layer, not read".
