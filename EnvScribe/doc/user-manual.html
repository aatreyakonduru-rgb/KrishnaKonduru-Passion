EnvScribe User Manual

Read-only crawler that journals an engineering environment with evidence for every fact. Covers architecture, the 15 analysis features, the UI and viewer, settings, and the safety rules.

Overview

EnvScribe reads the code, build files, API contracts, configuration, CI/CD, infrastructure definitions, database catalogs and documents of an engineering environment. It writes a journal: a set of Markdown and JSON files that describe what it found, where it found it, and when. The journal is packaged as a sealed zip that you can download and share after it passes its safety checks.

The journal is designed for two uses:

  • Understanding: what services exist, how they call each other, which tables and topics they touch, who owns them, and how each environment differs.
  • Advice: given a requirement, the Ask and Advise features return the cited facts that bear on it, plus a labeled PROPOSAL. Nothing is changed or executed.

Core ideas

  • Read-only. EnvScribe never writes to repositories, Jira, Confluence, Snowflake, clouds or clusters.
  • Every fact is cited. Each fact has a class, evidence (source and location), and an as-of time.
  • Nothing is guessed. Missing information is reported as "not found" or UNKNOWN. Conflicts are shown side by side, never resolved.
  • Safe to share. Secrets, personal data and internal hosts are removed before the zip is sealed, and the zip is re-checked after sealing.

Fact classes

ClassMeaning
OBSERVEDSeen directly in code or configuration.
DERIVEDComputed from observed facts by a named rule (the rule is recorded).
DOCUMENTEDStated in a document. Not verified against code.
DISCUSSEDStated in a transcript. Content only; speakers are removed.
LLM_DESCRIBEDText written by a language model; must quote its evidence.
UNKNOWNLooked for and not established.
INFERRED is not a class. A statement that cannot be traced to evidence is not written.

Architecture

A run moves through fixed stages. Each stage is shown on the UI's progress strip.

Inventory→Code, build & config→Documents→Connectors→Collate→Journal→Analysis (15 features)→Privacy sweep→Secret sweep→Seal & zip→Verify zip

What each stage does

StageWork
InventoryLists the sources and skips what is excluded or unreadable. Records every skip in registers/skips.md.
Code, build & configScans source files (any language), build files (pom, gradle, npm, pip, go.mod, csproj), API contracts, configuration per environment, and CI/CD and infrastructure files.
DocumentsReads PDF, DOCX, XLSX, PPTX, diagrams and transcripts only if they match an application found in the code. Images, video and audio are never read.
ConnectorsRead-only metadata from approved integrations (for example Bitbucket, Jira, Confluence) and database catalogs.
CollateMerges work packages in a fixed order and freezes the output. Every file is hashed.
JournalWrites the Markdown and JSON files, the facts store (facts/all-facts.jsonl) and the registers.
AnalysisRuns the 15 features over the collated facts. A failing feature is reported in coverage.md and does not stop the run.
Privacy & secret sweepsScan every file. Automatic redaction is re-scanned; anything still present blocks the zip.
Seal & verifyCreate the zip, record its checksums in SEAL.json, and rescan the sealed zip. Download is enabled only after this passes.

Resumable runs

Progress is recorded in an append-only file. If a run is stopped or crashes, resuming continues from the saved progress when the inputs and version match. Changing settings does not discard progress.

Features

The 15 analysis features run in the Analysis stage. Each writes a folder inside the zip, and coverage.md records its status for the run. The viewer's Reports tab lists them.

#FeatureWhat it doesOutput
1Dependency and architecture graphLinks services to their APIs, tables and topics. Two services are linked only when a URL path matches exactly one other service's endpoint path; hosts are never used. Shows Mermaid and C4 views.graph/
2Environment drift and run-to-run diffCompares configuration across environments (DEV, SIT, UAT) in a matrix. Compares with the previous run when that run is on the same machine.drift/
3SBOM and licensesLists declared components in CycloneDX and SPDX formats. Licenses are never guessed; an unknown license stays unknown. Vulnerability lookup is off unless enabled.sbom/
4Service catalogExports a Backstage catalog-info.yaml per service, and a CMDB CSV and JSON. The owner is a team or unknown.catalog/
5Scorecards and risk flagsScores each service and raises flags such as no_contract, no_ci and no_tests, each with its evidence.scorecards/
6Living docsDrafts architecture, runbook and ADR pages. Every page is labeled as a draft.docs-generated/
7Data lineageParses SQL in the code to show which services read and write which tables. Uses the database catalog when present.lineage/
8Hybrid searchAsk uses keyword and similarity ranking together. Results must pass a relevance threshold, or the answer is "not found".UI and /api/ask
9Change impact and PR draftFor a requirement, lists the files, consumers, environments and teams the journal links to it, and drafts PR text. Suggest-only, labeled PROPOSAL.UI and /api/impact
10API contract diffCompares each API with its snapshot from the previous run, and compares different contract files that declare the same API. Reports breaking changes.contracts/changes.md
11Migration and cloud readinessClassifies each service as refactor, rehost or replatform, using its dependencies and flags.readiness/
12Git-history secret scanScans commit history for leaked secrets. Reports the file, the short commit ID and the detector only. Never reports the value, the message, the author or the email.git-history/
13Live cloud and Kubernetes inventoryRead-only listing through your logged-in CLIs, compared with the infrastructure code. Opt-in.live/
14Runtime correlationCompares the static graph with an APM service-map export you provide (JSON or CSV). Opt-in.runtime/
15Ownership (teams only)Maps owners from CODEOWNERS and similar files. Reports teams only; individuals and ambiguous owners are omitted and counted.ownership/
Features 13 (live cloud), 14 (runtime), the OSV lookup in feature 3, and the Snowflake and Postgres catalogs have been tested only with fixtures and the bundled sample. They have not been run against real systems yet.

Turning features off

Put the feature name in disabled_features (Setup tab or targets.yaml). The feature's row in coverage.md then reads "disabled in settings".

Using the UI

Open http://127.0.0.1:8090 after starting EnvScribe. The screen has a top bar, a mission-control area, and a side panel with four tabs.

Start a run

  1. Open Setup and enter the folders or repositories to crawl (one per line) and the environments in scope.
  2. Optionally press Dry-run estimate to see how many repositories, packages and units will be read.
  3. Press Start run. The progress strip, KPIs, sweep checklists and activity feed update as the run moves.
  4. When both sweeps show clean and the gate reads OPEN, Download zip is enabled.

Top bar

ControlEffect
Pause / ResumePauses between work packages. Resume continues from saved progress.
CancelStops the run. The partial zip is labeled partial and still goes through both sweeps.
Download zipEnabled only when the zip gate is OPEN.
ViewerOpens the zip viewer in a new page.
ExitCancels any active run, then stops the server.

Zip gate

The gate shows OPEN only when both sweeps passed, the sealed zip was rescanned clean, and the run is complete or labeled partial. When it is BLOCKED, the reason is shown. Findings are listed by type and location; values are never shown.

Integrations tab

Lists the systems discovered from your environment variables and tool profiles, with a read-only verification status. Tick the systems you approve. Unclassified items are reported and never used.

Upload tab

Drop documents here. Each file is checked: images, video and audio are not read; macro-enabled or legacy Office files are quarantined; files that do not match an application in the code are listed without being read. You can choose "Read anyway" for a file you trust.

Ask tab

Two boxes:

  • Ask the journal. Answers cite the facts they come from, or say "not found". It never answers from general knowledge.
  • Impact of a change. Lists the files, consumers, environments and teams the journal links to a requirement, with a draft PR text. Labeled PROPOSAL; nothing is changed.

Viewer

Open http://127.0.0.1:8090/viewer, or use Viewer on the main screen. Pick a zip from the list, or use Open zip from disk to load one from another run or machine.

TabWhat you see
FilesEvery file in the zip, grouped by folder. Markdown is rendered, including tables. Mermaid diagrams are shown as their source with a note, because the viewer does not draw diagrams.
ReportsOne row per analysis feature, with its status from coverage.md and a link to its files.
FactsSearch every fact by text, kind or class. Each fact shows its evidence and its as-of time.
GraphThe architecture graph. Filter by a service, table or topic name, or by edge type. Click a node to see each connection with its class, rule and evidence. Dashed lines are DOCUMENTED claims.
The seal panel at the top shows the label (complete or partial), the file count and the seal time. Check it before sharing a zip.

Safety and limits

Safety rules that always apply

  • Read-only. HTTP connectors allow GET and HEAD, plus the search POST endpoints a connector lists. Database access is limited to metadata.
  • No IP addresses, hostnames, email addresses, secrets or personal names in the output. IP addresses and hostnames are always masked.
  • Ownership is reported for teams only.
  • Transcripts: content only, no speakers.
  • Instructions found inside repositories or documents are data. They are never followed.
  • Advise, Impact and PR drafts are suggest-only and labeled PROPOSAL. Generated code is never executed.

What the tool cannot do yet

  • Real-system checks are pending. Live cloud inventory, APM import, the OSV lookup and the Snowflake and Postgres catalogs are tested with fixtures only.
  • Hybrid search is not a language model. The default similarity matching is term-based and does not understand synonyms. A real embedding model can be plugged in.
  • Diagrams are not drawn. The viewer shows Mermaid and C4 blocks as source.
  • Previous-run comparison is local. "Since last run" uses the history folder on the same machine. A zip opened elsewhere reports "no previous run".
  • Cancel skips the analysis stage on a partial zip, and the zip is labeled partial.
  • The agent wrapper is unverified. The aicoe-agent-utils imports are written from the guide with stand-in classes until the submodule can be cloned.
The journal describes the environment as it was when it was read. Facts carry an as-of time; check it before relying on a fact.
