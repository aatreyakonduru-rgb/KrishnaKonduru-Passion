```
python tools/kb_links.py check <KB> [--no-write]                        # exit 1 if a link is broken; orphans do not change the exit code
python tools/kb_trend.py record <KB> | show <KB> [--last N]
python tools/telemetry_lines.py record <KB> --answer FILE [--by NAME] | report <KB> [--limit N]
```

## Behaviour and limits (honest)
**kb_contradict**
- Pattern matching, no model. Claims come from table rows (header = attribute, first cell = entity; Attribute/Value tables under a heading), `X schedule: v`
  lines, `schedule of X is v`, `X is owned by Y`, `X runs at/every ...`, `X has N things`, `X runs on Y`, `X is written in Y`, `X uses Y`, `X is a Y`.
  A pair is two claims on different pages, same normalised subject and attribute, values neither equal nor one inside the other (`nightly` vs
  `nightly at 02:00` agree). Numbers compare as numbers.
- Confidence is the reliability of the pattern (high: table/key-value/count; medium: owner, schedule, type, platform sentences; low: `uses`, plain `is`),
  not the likelihood the pages truly conflict. Many flags will be false (same name, two things; per-environment values). It cannot see contradictions
  phrased differently, across a paragraph, or in prose with no pattern. Pairs are capped at 10 per subject/attribute. Judgement states a reading of the two lines only.
- `--raise` is explicit and needs `--by`; the UI action needs a named lead. Raised through `questions.cmd_raise` (reuses an open question with the same words).
  Question type comes from the top folder (db -> data, etl -> etl-batch, modules/app -> application, else business), as `feedback.py` does. Nothing edits a page.
- Staged batch: staged `.md` replaces the live page of the same path, `.DELETE` removes it; only pairs with a staged side are reported. A pair id is a hash of
  subject, attribute and the two values, so a judgement survives re-scans while the values stay the same.

**llm_judge**
- Verdict wording is "supported by the quoted source text" etc. (`SAYS`); a note says it is not a claim of correctness. Lexical results from `golden.score` and
  `verify_kb` are reported untouched beside the judged ones; `flag` marks disagreement (lexical pass + unsupported, lexical fail + supported). Nothing is replaced.
- File judge: request has claim, quote, source window (+/-2 lines for line refs, +/-3 around a quote), expected pages, `write_verdict_to`. Request id hashes content,
  so an edited line gets a new request. Bad verdict files are reported as errors, not accepted. Needs a Devin/Bob session to write verdicts.
- HTTP judge: OpenAI-compatible chat completions via `urllib`; key read from the env var named in `judge.api_key_env`, sent only as a header, never stored/logged;
  `https` required except loopback. **Needs your environment to verify: tested only against a fake opener.** Sends KB lines and source text to that endpoint.
- Sources not shown to a judge: `doc:`, `answer:`, `settings:` tags and unreadable repo files are listed as "unavailable", not judged.
- Profile keys read (under `judge`): `endpoint`, `model`, `api_key_env`, `timeout`. See hooks.

**kb_dupes**: 5-word shingles; candidates by SimHash band match or MinHash share (a pair at the 0.8 threshold is missed with probability under 0.1%); decision is exact
Jaccard. A paragraph pair is dropped when its two pages are already reported as a page pair. Pairs capped at 5 per page/paragraph; 200 paragraph pairs overall; pages under 30 words ignored.

**kb_links**: inline and reference links, GitHub heading slugs. Not checked: external URLs, anchors on non-Markdown files, HTML `<a href>` links, links inside code.
Orphan = hand-written page, not in a root folder, no inbound link, not listed (link or path text) in an index page (index/README/*_INDEX or first heading Index/Contents).

**kb_trend**: counts only (no text/names). Series for the UI: source-check problems, objects named in no page, open questions, golden static problems, contradiction
pairs, duplicate page pairs, broken links, pages. `record` runs `verify_kb.Checker.run()` unless you pass the result in (`record(kb, verify=rep)`) to avoid a second pass.
It does not run golden scoring (needs answers). `.metis/trend.jsonl` is local; it is not git-ignored by this tool and is not in `kb_manifest.LOCAL`, so see the hook below.

**telemetry_lines**: records `path:line` only (quotes are located in the file and stored as line numbers; no quote, question or answer text). Join uses the answer copies
`_FEEDBACK/answers/F-xxxx.md`, so past ratings count. Line numbers drift if a page is edited; a vanished line is shown as "line no longer exists". Range capped at 20 lines/tag.
Ratings are per answer, so "look first" is not a verdict (stated on the page and in the CLI).

**screens_quality**: read-only. Only action `/quality/raise` (leads only, via `kb_gate.who`). Every user/report string is escaped. A broken report shows an error box on that tab, not a crash.

## Hooks for the integrator (exact text; I did not edit these files)

1. `tools/build_outputs.py`: add imports and calls (after `verify_kb` result `rep` is computed, before the gate lines). Suggested:
   ```python
   import kb_contradict  # noqa: E402
   import kb_dupes  # noqa: E402
   import kb_links  # noqa: E402
   import kb_trend  # noqa: E402
   ...
   # after: kb_manifest.main(["generate", kb])   and before: rep = verify_kb.Checker(kb).run()
   kb_contradict.write_report(kb, kb_contradict.build(kb))
   kb_dupes.write_report(kb, kb_dupes.build(kb))
   kb_links.write_report(kb, kb_links.check(kb))
   # after: rep = verify_kb.Checker(kb).run() and its printing
   kb_trend.record(kb, rep)
   ```
   Order matters for the manifest: if the three reports are written after `kb_manifest.main(["generate", kb])`, `kb_manifest validate` will report them as added. Write them
   before the manifest step. `kb_trend.record` writes under `.metis/`, which is not in the manifest's SKIP list: add `".metis/trend.jsonl"` to `kb_manifest.LOCAL`
   (`LOCAL = (".metis/usage/", ".metis/graph.sqlite", ".metis/trend.jsonl", ".metis/judge/", ".metis/contradict/")`), otherwise `kb_manifest validate` fails after the first record.
   (`.metis/judge/` and `.metis/contradict/` have the same issue once files are written there.) `kb_trend.record` is append-only: a rebuild adds a line.
   Note the three CROSS-LAYER reports also are "governed" by `kb_gate` once locked (not in `DERIVED`): add `"CROSS-LAYER/CONTRADICTIONS.yaml"`, `"CROSS-LAYER/DUPLICATES.yaml"`,
   `"CROSS-LAYER/LINK_CHECK.yaml"` to `kb_gate.DERIVED`, or each build on a locked KB will list them as "not certified (new)".
2. `tools/ui/answers.py` (two places, lines ~428 and ~485: `telemetry.record(kb, "answer", r["files"], by=...)`): to get per-line attribution add `lines=telemetry_lines.cited_lines(kb, text)`
   (the answer text is in scope as `text` in `ask`; in the second place read the answer file text). `lines=` is optional and the call stays valid without it.
3. `templates/kb-profile.yaml`: optional new block (all empty by default; empty means the file judge is used):
   ```yaml
   judge:
     endpoint: ""        # OpenAI-compatible chat completions URL, https (http only on this machine)
     model: ""
     api_key_env: ""     # NAME of an environment variable that holds the key; never put the key here
     timeout: 60
   ```
4. `ui/ui_common.py` `RAIL_ICON`: optional `"/quality": ("&#10003;", "Quality")`. Without it the rail shows a default dot with the first 8 letters of the label.
5. `.gitignore` for KBs: add `.metis/trend.jsonl` if trend should stay local (it is counts only, so committing it is also fine).
6. `kb_gate.DERIVED` / manifest: see item 1.
